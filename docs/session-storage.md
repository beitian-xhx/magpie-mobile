# P1 原生会话持久化（0.1.8）

## 已实现范围

- Room v1 保存 conversation、message、operation、metadata，不复制 Go 提供商/模型/路由配置或凭据。
- 原生历史列表每批 30 会话，消息每页 50 条；查看历史不需要启动网关，不调用模型。
- 每次显式发送前先事务保存 RUNNING + user；成功后事务保存 assistant + SUCCEEDED，失败保存固定脱敏摘要 + FAILED。
- 启动恢复把上次进程留下的 RUNNING 标为 INTERRUPTED/结果未知；不补造回答，不自动重发。
- 下次显式发送只恢复 SUCCEEDED 完整 user/assistant 对；不携带失败、部分输出或旧版不明边界记录。
- ViewModel 持有发送和内存草稿，屏幕旋转不新发请求；私有连接变化后拒绝旧请求，不自动换模型。退出 Activity 前未发送的任务在上下文读取/事务边界检查取消；已经进入阻塞 HTTP 的请求不能保证即时取消，可能继续到增量回调/超时，服务商可能已经计费，不承诺退出等于未发送。本阶段没有独立“停止生成”按钮。

## 旧数据迁移与安全

旧 JSONL 没有 conversation/turn ID，也混合成功、失败和多次“新会话”，不能可靠恢复上下文。导入成一份只读旧版存档，原文件绝不删改；导入与完成 marker 原子提交，重启不重复导入。坏行计数并显示固定提醒；16 MiB 文件/256 Ki 字符单行限额、UTF-8 严格读取，失败回滚且可以重试读取。原文在原文件保留。

数据库存于 App 私有目录，受 Android FBE 保护，不宣称逐字段加密。系统备份关闭；本阶段没有明文导出或网络同步。失败摘要只接受固定 HTTP 状态/流分类和部分长度，不保存上游自由错误正文、异常栈或 partial。用户主动输入的聊天正文仍可能包含敏感信息，请勿把 API Key 当聊天内容发送。

Room schemaVersion=1，已从实际通过的 KSP 构建导出结构并提交版本化 schema；CI 在测试后校验重新生成结构与基线一致，变化必须经过显式迁移审查。未来升级必须提供显式迁移并验证旧数据。不设置 destructive migration；打开或校验失败保留原库并阻止发送，不删除重建。

## 有意保留的边界

成功上下文上限 40 轮、65,536 字符；超出保留历史并要求新建会话，不静默截断。未发送草稿只留内存；进程退出后未发送草稿不恢复，已开始请求的 user 可从中断记录读取并手工选择后续操作。失败 partial 仅内存预览，不持久化为成功消息。

本阶段不是完整 Sessions/备份子系统：DataStore 偏好/启停意图、SAF 与 M4 加密备份、核心会话导入、回收站、删除/保留策略、完整导航后续单独推进。新建会话不会删除旧会话。

## 验收

Actions 跑 core JVM、Room/Robolectric、ViewModel synthetic SSE、Python/Go/host 假上游回归，并核对 APK native SHA；不调用真实渠道。测试定义/静态检查不等于测试通过，以最终提交 Actions 为准。

真机待确认：旧数据导入提示、离线查看历史、旋转时只发一次、重启后中断标记、键盘/小屏/长消息布局。0.1.8 起使用 GitHub Secrets 固定 Release 签名，证书 SHA256 为 dee1d3f485ee17a6184178eaab318d6333fb8b67e7276146a30a03e1f9ee09d6；CI 缺少 Secret 或证书不匹配即拒绝发布。密钥/密码不提交源码或公开附件，runner 暂存仅私有权限。用户已明确允许上传签名密钥到 GitHub Secrets。

已核验旧 0.1.6 和 0.1.7 的真实 APK 哈希及签名：分别为不同 Android Debug 公钥/证书，且没有 v3 签名轮换链。因此新固定签名不能覆盖这些旧包，不能把新生成 Key 称为旧签名恢复。签名不匹配时保留旧 App，不卸载/清数据；旧配置安全迁移方案需要另行确认。
